# 接口与异常边界审查

日期：2026-10-28。

## 状态与范围

本次修复归入 1.0.0-rc.13，基于 rc.12，不是既有 rc.12 标签的重新验收，也不是生产放行。源码和预编译 dist 已更新，母工程同步了相同插件修复；审查阶段没有推送、安装到个人 Pi、部署容器、启动靶场或改动用户模型配置及数据库；后续 GitHub 发布不改变本报告的验收范围。

本轮检查主会话与 Worker 的工具声明、模型终态与重试、IPC、证据保存、状态读写、取消、会话压缩/切换、协作恢复、图响应与未知写入、并发额度、长作业监督。没有新增运行平台、通用重试框架或替代 Pi 的模型循环。

## 发现与修复

| 问题 | 修复与验证依据 |
| --- | --- |
| 主会话 rt_campaign 根 schema 缺少 object 类型，网关可能拒绝整轮请求 | 模型声明使用对象参数，执行仍按 action 严格校验；检查实际 Pi OpenAI-compatible 请求序列化结果 |
| Worker rt_team 也使用顶层联合，主会话测试无法覆盖 | 改为对象声明，保留执行时判别校验；独立检查 Worker 协作和复制的四个领域工具 |
| Pi 的 prompt 可以正常返回，但最终模型消息为 error、aborted 或 length | Worker 检查本轮最终消息与显式取消，返回错误而非成功；不把成功的 Pi 内建重试当成失败 |
| 输入已由扩展处理、没有本轮模型响应时，旧助手文本被当成本轮结果 | 每轮清空响应跟踪，没有新回复时返回空文本，不查找以前的助手回答 |
| 错误在 Worker IPC 和监督状态里变为无原因的 failed | 协议新增有界诊断，父端错误与监督记录保留原因；初始化和 Worker 扩展错误也保留诊断 |
| Worker 证据保存异常逃逸出工具结果钩子，导致 Worker 停止而原始输出丢失 | 保留原生结果和结构化输出，增加持久化未验证提示；不会因此重放命令或伪造证据 |
| 畸形图响应以普通异常逃逸，未进入图错误结构与冷却 | 无效信封、非 JSON、无效行、重复 ID、超限快照明确报错；合法空数组仍然是空图；未知写入不自动重放 |
| 后台 Worker 失败处理若再次遇到 IO/通知异常，会形成未处理拒绝 | 失败清理再次异常触发现有有界停止路径，不创建新的任务/模型循环 |
| 停止时保存检查点失败，内存仍显示 runtimeStopVerified=true | 内存保留 attention 和 false，停止调用继续拒绝，要求人工核查；不声称持久化已完成 |
| 原子写/重命名失败遗留临时文件，长任务反复失败会堆积 | 尝试清理本次临时路径并保留原始异常；不删除原目的地，不声称同步失败已回滚 |

最后一项清理若也遭遇 IO/权限故障，只能尝试，不能承诺临时文件一定消失。原子重命名后的目录同步失败也不等于写入被回滚；调用者仍需要检查当前状态。

## 检查过并保留的边界

- Pi 继续管理原生会话、上下文压缩和 provider 重试。插件没有另加循环，400/schema 错误不会由 Worker 监督循环伪装成成功后继续推进。
- 会话切换、停止与失效通知不得启动迟到轮次；恢复不扩大原截止时间、累计轮次、工具集合或父交接额度。
- 同一工作不能被两个进程同时认领；无效/过期租约不能修改工作结果；重新指派后旧租约不能发表有效完成。
- 无图环境正常降级，图专属工作保持 blocked；关闭插件图增强不等于关闭原生 MCP。
- 写入未知、控制进程中断、无法核验终态不自动重放，也不转译为漏洞不存在或整体任务成功。
- 返回错误不清空已保存的证据或整个案件状态，低层存储异常不转换为新的空状态。

## 仍需验收

1. 用户实际使用的模型网关：主会话和 Worker 的请求声明、工具结果、provider 重试、上下文压缩与重连。当前使用合成 provider、真实 SDK 和本地请求序列化，未调用用户模型服务。
2. 新版本的实际安装包与 Kali 镜像：现有发布包、旧镜像、rc.12 标签没有自动获得这些修改。不能拿旧发布哈希为本轮代码背书。
3. 独立真实 Neo4j 的本轮集成，以及实际部署权限/网络边界。本轮新增图测试是故障注入，不把旧数据库集成结果冒充本轮结果。
4. 多天任务、断电/容器删除、真实资源耗尽。有限故障回归不能证明任意失败组合都可靠。

下一步先发新的热修复版本，再做最小真实网关验收，最后重跑授权靶场。升级前停止并核验旧 Worker/长作业，退出 Pi，再更新整个插件；不要让旧 Worker 和新父进程混用协议。容器重建不是热更新。
