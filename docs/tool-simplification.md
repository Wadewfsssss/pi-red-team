## 保留的四个工具

| 工具 | 不由 Pi 原生工具替代的职责 | 边界 |
| --- | --- | --- |
| rt_search | 持久候选假设、TDI/UCB 建议、逻辑尝试与证据反馈 | 不替模型决策、不执行动作、不判定整体成功 |
| rt_graph | 证据关系与路径／前置条件推理 | 经 Pi 原生 MCP；不另造数据库连接管理 |
| rt_job | 长命令监督、增量输出、取消与不确定状态核验 | Linux/Kali 后台进程，不自动重放未知命令 |
| rt_team | 动态 Worker 的有界委派、认领、共享证据与交接 | Pi 原生子会话，不接管父模型循环 |

/rt status、doctor、graph 是诊断／设置命令，不是新增模型工具。Worker 的 rt_team 是受限认领接口，不能启动或扩大团队；与父工具同名但不是重复主控。

rt_search recommend 给出候选评分，next 产生带决策标识的下一步建议；rt_graph paths 返回指定端点候选路径，query chains 给出证据链分析。操作存在相关性，但不形成独立冗余账本，本次不盲删；今后只有调用轨迹证明可以合并时再精简。

覆盖、授权、交付和停止依据来自专家任务及外部规则。可选覆盖笔记使用 Pi 原生 read/write/edit。无候选、批次结束或预算耗尽都不等于整体成功。仍不强迫单步任务调用领域工具。
